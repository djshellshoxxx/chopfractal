# F15 Cross-platform builds and packaging

**Status:** Ready for development (steps 1-6 need no secrets; steps 7-10 need the maintainer items in section 3)  **Size:** L (10 engineer-days plus maintainer lead time for certificates)  **Depends on:** none for build/CI work; F11/F12/F13 only add rows to the manual test matrix  **Blocks:** any public beta or sale

## 1. Summary and user value
Today only Linux builds the JUCE VST3 (`plugin-linux` in `.github/workflows/ci.yml`); macOS arm64 and Windows MSVC build and test only the portable modules (BUILD_STATUS stage 7/8: "macOS and Windows plugin builds, installers and signing: not run"). This feature makes ChopFractal installable on the two platforms producers actually use: a universal (arm64 + x86_64) macOS VST3 and a Windows x64 VST3, both validated by Steinberg's validator in CI, built from one version number, signed (macOS Developer ID + notarization, Windows Authenticode), shipped as an installer, released from a tag, with third-party notices, crash-safe diagnostics and a documented real-DAW test matrix.

## 2. User stories and scope
- As a producer on macOS (Apple silicon or Intel) I download one `.pkg`, double-click, and the plugin appears in my DAW without Gatekeeper warnings.
- As a producer on Windows 10/11 x64 I run one setup `.exe` signed by a known publisher and the plugin appears in my DAW; the uninstaller removes it.
- As the maintainer I push a tag `v0.2.0` and get signed, notarized, checksummed artifacts on a GitHub Release, and CI refuses to ship if the license/JUCE decision is unmade.
- As a tester I have a matrix of hosts and a script to fill in.
- **In scope:** CI jobs `plugin-macos`, `plugin-windows`; validator on three OSes (`tools/validate_vst3.sh`); `VERSION` single source and version stamping; signing/notarization scripts and procedure with secret handling; installers (macOS `.pkg`, Windows Inno Setup); `.github/workflows/release.yml`; artifact naming; JUCE license gate; third-party notices bundle; crash-safe file logging and About/diagnostics; `docs/RELEASING.md`, `docs/COMPATIBILITY.md`; manual DAW matrix; flip MSVC warnings to errors.
- **Non-goals:** AU/AAX/CLAP/standalone formats, Logic Pro (AU only, out of scope), Linux packages beyond an unsigned `.tar.gz`, auto-updater, licensing/serial/activation system, a crash-reporting service or uploading logs, Windows ARM64, 32-bit, macOS before 11.0, Windows before 10 21H2, MSI/WiX (Inno chosen; see 6).

## 3. UX
User-visible parts (everything else is CI/tooling):
- **About box** (opened from StatusBar's `"i"` button, F00; a `juce::AlertWindow`/small modal): title `"ChopFractal 0.1.0 (build 123, a1b2c3d)"` (`"Development build"` appended when `CHOPFRACTAL_RELEASE` is off); body `"VST is a trademark of Steinberg Media Technologies GmbH."`; buttons `"Third-party notices"` (opens `<install dir>/THIRD_PARTY_NOTICES.txt` via `juce::File::startAsProcess`), `"Open log folder"`, `"Copy diagnostics"`, `"Close"`. Messages: `"Diagnostics copied to the clipboard."`, `"Could not open the log folder."`, `"The notices file was not found. Reinstall ChopFractal."`.
- **Diagnostics text** (clipboard): version, build, git sha, OS, CPU arch, host name (`juce::PluginHostType::getHostDescription()`), sample rate, block size, bus layout, parameter manifest version, last 50 log lines. No paths of user audio, no project contents.
- **Installer UI strings (both platforms):** product `"ChopFractal"`, publisher `"<Publisher name>"` (maintainer decision), pages: Welcome, License (EULA text `installer/EULA.txt`, maintainer-supplied; installer refuses to build with the placeholder text), Install location (fixed, shown read-only), Finish `"Open your DAW and rescan plugins. ChopFractal appears under VST3 > ChopFractal."`. Install targets: macOS `/Library/Audio/Plug-Ins/VST3/ChopFractal.vst3`; Windows `%CommonProgramFiles%\VST3\ChopFractal.vst3` (64-bit common files). Uninstall: macOS via `sudo rm -rf` documented in `docs/RELEASING.md` plus pkg receipt `com.chopfractal.pkg.vst3`; Windows via Apps & Features / `unins000.exe`.
- Maintainer decisions required (open items, cannot be resolved from the repo; each has a CI variable or secret):
  1. Apple Developer Program membership (Team ID), one "Developer ID Application" and one "Developer ID Installer" certificate, an App Store Connect API key (Issuer ID, Key ID, `.p8`).
  2. A Windows code-signing route: Azure Trusted Signing account (needs eligible organization/individual verification) or an OV/EV certificate from a CA with cloud/HSM signing (since 2023 CAs issue keys on hardware/HSM; a plain `.pfx` is only possible for pre-existing certificates). Without it, installers are built unsigned and named `...-UNSIGNED...`; Windows SmartScreen will warn.
  3. The JUCE license route (AGPLv3 vs paid commercial) from `docs/LICENSING.md`, and the final `LICENSE`/EULA text. A closed-source release requires the JUCE commercial license.
  4. Publisher name, support URL, bundle identifier domain (default below), minimum OS versions, whether Linux ships.
  5. Steinberg VST3 terms check for the bundled SDK (JUCE 8.0.15 reports SDK 3.8.0, which Steinberg publishes under MIT; confirm in the shipped `VST3_SDK/LICENSE.txt`) and trademark text.

## 4. Data model and state
No plugin state, parameter, or schema change. Host parameter IDs, `PLUGIN_MANUFACTURER_CODE Cfrc`, `PLUGIN_CODE Cfx1` stay permanent (changing them changes the VST3 class ID and orphans every user project); the parameter manifest version is unchanged (2). Golden hashes unchanged: 2397844821793184813, 12084884237330071892, 13710596758976548913, 18237151833431327128.
Build/release data:
- **`VERSION`** (repo root, one line, `MAJOR.MINOR.PATCH` with optional `-beta.N`/`-rc.N`; initial `0.1.0`) is the only source. Root `CMakeLists.txt` reads it (`file(STRINGS VERSION CF_VERSION_FULL)`, `string(REGEX MATCH "^[0-9]+\\.[0-9]+\\.[0-9]+" CF_VERSION_NUM ...)`, `project(ChopFractal VERSION ${CF_VERSION_NUM} LANGUAGES CXX)`). `plugin/CMakeLists.txt` passes `VERSION ${PROJECT_VERSION}`, `BUILD_VERSION ${CHOPFRACTAL_BUILD_NUMBER}` (CI run number, default 0), `BUNDLE_ID com.chopfractal.ChopFractal` to `juce_add_plugin` (macOS CFBundleShortVersionString/CFBundleVersion, Windows file/product version resource). `configure_file(src/BuildInfo.h.in ...)` generates `BuildInfo.h` with `kVersionFull`, `kVersionNum`, `kBuildNumber`, `kGitSha` (`git rev-parse --short=7 HEAD` at configure time, `"unknown"` outside git), `kIsRelease`. Module `module.json` versions (0.1.0 each) are API versions and are NOT tied to this file. `tools/check_version.py` (CI `portability` job) asserts: `VERSION` format; root CMake reads it; installer scripts contain no literal version; on tags, `refs/tags/v<VERSION>` matches exactly.
- **CMake options** (plugin/CMakeLists.txt, root): `CHOPFRACTAL_RELEASE` (OFF), `CHOPFRACTAL_JUCE_LICENSE` (`UNSET` | `AGPL` | `COMMERCIAL`, default `UNSET`), `CHOPFRACTAL_BUILD_NUMBER` (0), `CHOPFRACTAL_UNIVERSAL` (ON on Apple). **License gate:** with `CHOPFRACTAL_RELEASE=ON` configure fails with `message(FATAL_ERROR "Release builds need a JUCE license decision. Set -DCHOPFRACTAL_JUCE_LICENSE=COMMERCIAL (you hold a JUCE commercial license) or AGPL (the whole plugin is published under AGPLv3). See docs/LICENSING.md.")` when `UNSET`; `AGPL` additionally fails unless `LICENSE_ID` contains `AGPL-3.0` ("AGPL release requires LICENSE_ID=AGPL-3.0-or-later; run tools/set_license.py"). `COMMERCIAL` is an attestation; the release workflow reads it from the repository variable `JUCE_LICENSE` (set by the maintainer after buying) and refuses to run when the variable is missing.
- **Artifact naming** (`<ver>` = `VERSION` content; pre-release CI builds use `<ver>+<sha7>`): `ChopFractal-<ver>-macos-universal-vst3.pkg`, `ChopFractal-<ver>-windows-x64-vst3-setup.exe`, `ChopFractal-<ver>-linux-x86_64-vst3.tar.gz` (only if Linux ships), `SHA256SUMS.txt`, `THIRD_PARTY_NOTICES.txt`. Unsigned fallbacks insert `-UNSIGNED` before the extension and are never attached to a GitHub Release (only to workflow artifacts, retention 14 days).
- **Notices:** curated `docs/third_party/NOTICES.md` (JUCE 8.0.15 and the JUCE-bundled third-party components that are compiled in: VST3 SDK, plus whichever of zlib, libpng, libjpeg, FreeType/HarfBuzz/SheenBidi, FLAC and Ogg Vorbis the build links; each with SPDX id, version, upstream URL and full copyright/license text copied from the JUCE 8.0.15 tree). `tools/check_notices.py` (CI) fails if the JUCE tag in `plugin/CMakeLists.txt` differs from the one in the notices file, or if a JUCE module linked by `plugin/CMakeLists.txt` has no section. `tools/gen_notices.py` assembles `THIRD_PARTY_NOTICES.txt` (this notices file + `LICENSE` of ChopFractal + the Steinberg trademark sentence) for installers. Portable modules need no entry (`third_party: []`).

## 5. Public API
No C++ API. Tooling contracts (all runnable locally; none read secrets from files in the repo):
```
tools/validate_vst3.sh <bundle>                       # extended: Linux, macOS (universal validator), Windows (Git Bash, VS generator)
tools/package_macos.sh   --bundle <path> --version <ver> --out <dir> [--sign-identity <id>] [--installer-identity <id>]
tools/sign_macos.sh      <bundle-or-pkg>              # env: MACOS_SIGN_IDENTITY / MACOS_INSTALLER_IDENTITY, keychain already unlocked
tools/notarize_macos.sh  <pkg>                        # env: APPLE_API_KEY_ID, APPLE_API_ISSUER, APPLE_API_KEY_PATH; runs submit --wait, staple, validate
tools/package_windows.ps1 -Bundle <dir> -Version <ver> -Out <dir> [-Sign]
tools/sign_windows.ps1   -Files <paths>               # mode from $env:CF_WIN_SIGN_MODE = azure | pfx | none
tools/check_version.py   [--tag refs/tags/vX.Y.Z]
tools/check_notices.py   ; tools/gen_notices.py --out <file>
tools/verify_bundle.py   --platform macos|windows|linux --bundle <path> --expect-version <ver>
```
`tools/verify_bundle.py` assertions: macOS: `lipo -archs` equals the set `{x86_64, arm64}`, `Contents/Info.plist` `CFBundleShortVersionString == VERSION numeric`, `CFBundleIdentifier == com.chopfractal.ChopFractal`, `codesign --verify --strict --deep` when signed, `spctl -a -t exec -vv` on release; Windows: PE machine `0x8664`, `FileVersion` equals `<num>.0`, `Get-AuthenticodeSignature` status `Valid` when signed, bundle layout `ChopFractal.vst3/Contents/x86_64-win/ChopFractal.vst3`; Linux: ELF x86-64, `Contents/x86_64-linux/ChopFractal.so`.
Plugin code (JUCE shell only, `plugin/src/Log.h/.cpp`, message/worker threads only): `namespace cflog { void init(); void info(const juce::String&); void warn(const juce::String&); void error(const juce::String&); juce::File folder(); juce::String tail(int lines); }`. Never called from `processBlock`.

## 6. Behavior details and edge cases
**CI jobs (`.github/workflows/ci.yml`, both HOT):**
- `plugin-macos` on `macos-14`: cache `~/.cache/chopfractal-vst3sdk` and `build-plugin/_deps` (key includes `runner.os`, hash of `plugin/CMakeLists.txt`, `tools/validate_vst3.sh`); `cmake -S . -B build-plugin -G Ninja -DCHOPFRACTAL_BUILD_PLUGIN=ON -DCMAKE_BUILD_TYPE=Release -DCMAKE_OSX_ARCHITECTURES="arm64;x86_64" -DCMAKE_OSX_DEPLOYMENT_TARGET=11.0 -DCHOPFRACTAL_BUILD_NUMBER=${{ github.run_number }}`; build `ChopFractal_VST3 ChopFractalShellTests`; run shell tests natively (arm64; the editor test runs, GitHub macOS runners have a GUI session; the test already skips when no display exists); `verify_bundle.py --platform macos`; validator on the arm64 slice natively and on the x86_64 slice with `arch -x86_64 <validator>` (validator built universal by the script). If Rosetta is unavailable on the runner, the x86_64 validation step is `continue-on-error: false` only for release builds and the matrix row "macOS Intel" in section 7 becomes mandatory manual QA.
- `plugin-windows` on `windows-2022`: `cmake -S . -B build-plugin -G "Visual Studio 17 2022" -A x64 -DCHOPFRACTAL_BUILD_PLUGIN=ON -DCMAKE_MSVC_RUNTIME_LIBRARY=MultiThreaded` (static CRT: no VC++ redistributable dependency; `cmake_policy(SET CMP0091 NEW)` already implied by `cmake_minimum_required(3.22)` in `plugin/`); `cmake --build build-plugin --config Release --target ChopFractal_VST3 ChopFractalShellTests`; run `ChopFractalShellTests.exe`; `verify_bundle.py --platform windows`; validator (built with MSVC by the script into the cache) on `ChopFractal.vst3`. Shell: `bash` (Git for Windows) for `tools/*.sh`.
- `tools/validate_vst3.sh` changes: detect OS with `uname -s` (`Linux`, `Darwin`, `MINGW*|MSYS*`); generator `Ninja` on Linux/macOS, `Visual Studio 17 2022 -A x64` on Windows; add `-DCMAKE_OSX_ARCHITECTURES="arm64;x86_64"` on Darwin; validator path `$cache/build/bin/Release/validator` or `.../validator.exe`; cache directory keyed by OS; exit code propagated; prints the validator summary line (`Result: N tests passed, 0 tests failed`) and fails if the failed count is not 0 (parse, do not rely only on exit status). The Linux job is unchanged except for using the extended script.
- `build-test` matrix: flip `windows-msvc` to `werror: "ON"` after fixing the MSVC `/W4` findings (BUILD_STATUS lists this as not yet exercised); add `macos-x86_64` row built on `macos-14` with `-DCMAKE_OSX_ARCHITECTURES=x86_64` running tests under Rosetta (`arch -x86_64 ctest`).
- Pull requests from forks never receive secrets and never sign; `plugin-*` PR jobs build unsigned artifacts (retention 14 days).
**Release workflow `.github/workflows/release.yml`:** triggers `push: tags: ["v*.*.*"]` and `workflow_dispatch` (input `dry_run`, default true: runs everything but skips publishing). Jobs in order: (1) `gate` (ubuntu): `tools/check_version.py --tag $GITHUB_REF`, repository variable `JUCE_LICENSE` present and in {AGPL, COMMERCIAL}, `tools/check_notices.py`, `ctest` portable suite; (2) `build-macos` (`environment: release`), (3) `build-windows` (`environment: release`), (4) `build-linux` (only when repository variable `SHIP_LINUX == "true"`), (5) `publish` (`needs` all, `permissions: contents: write`): downloads artifacts, generates `SHA256SUMS.txt` (`sha256sum`), creates the GitHub Release (draft until the maintainer publishes; prerelease flag when VERSION has `-`), attaches files, release notes from `CHANGELOG.md` section for the version (the job fails if absent). Signing steps run only in jobs with `environment: release` (protected: required reviewer = maintainer, deployment branches/tags `v*`), so secrets are unavailable to ordinary workflows.
**macOS signing/notarization procedure (`build-macos`):** 1) create a temporary keychain `build.keychain` with a random password (`openssl rand -base64 24`, masked), import `MACOS_APP_CERT_P12_BASE64` and `MACOS_INSTALLER_CERT_P12_BASE64` (decoded to `$RUNNER_TEMP`, deleted immediately after `security import`; `security set-key-partition-list -S apple-tool:,apple: -s -k ...`); 2) build as in CI with `-DCHOPFRACTAL_RELEASE=ON -DCHOPFRACTAL_JUCE_LICENSE=${{ vars.JUCE_LICENSE }}`; 3) `codesign --force --timestamp --options runtime --sign "$MACOS_SIGN_IDENTITY" ChopFractal.vst3` (hardened runtime; no `--deep`; no entitlements are needed because the plugin loads no external dylibs and uses host-provided audio/file access); `codesign --verify --strict --verbose=2`; 4) `tools/package_macos.sh`: `pkgbuild --root <staging> --identifier com.chopfractal.pkg.vst3 --version <num> --install-location /Library/Audio/Plug-Ins/VST3 component.pkg` then `productbuild --distribution distribution.xml --resources installer/macos/resources --package-path . --sign "$MACOS_INSTALLER_IDENTITY" --timestamp out.pkg` (distribution.xml has welcome, license = EULA, conclusion text; `hostArchitectures="arm64,x86_64"`; minimum OS 11.0); 5) `xcrun notarytool submit out.pkg --key "$APPLE_API_KEY_PATH" --key-id "$APPLE_API_KEY_ID" --issuer "$APPLE_API_ISSUER" --wait --timeout 30m` (fail on status other than `Accepted`; on failure upload `notarytool log <id>` as an artifact); 6) `xcrun stapler staple out.pkg` and `stapler validate`; `spctl -a -t install -vv out.pkg` must report `accepted source=Notarized Developer ID`; 7) always-run cleanup: `security delete-keychain build.keychain`, remove `$RUNNER_TEMP` key files. Secrets: `MACOS_APP_CERT_P12_BASE64`, `MACOS_APP_CERT_PASSWORD`, `MACOS_INSTALLER_CERT_P12_BASE64`, `MACOS_INSTALLER_CERT_PASSWORD`, `APPLE_API_KEY_P8_BASE64`; variables (non-secret): `MACOS_SIGN_IDENTITY`, `MACOS_INSTALLER_IDENTITY`, `APPLE_API_KEY_ID`, `APPLE_API_ISSUER`, `APPLE_TEAM_ID`. Rules: secrets only as `env:` of the single step that needs them; never `set -x` in those steps; `::add-mask::` for derived values; no secret in artifact names or logs; certificate expiry (5 years) tracked in `docs/RELEASING.md` with a calendar reminder; rotate API key annually. Ad-hoc signing (`codesign -s -`) for unsigned CI builds so Apple-silicon hosts can at least load the local build after removing quarantine.
**Windows signing/installer (`build-windows`):** build with `-DCHOPFRACTAL_RELEASE=ON`, static CRT; install Inno Setup 6 (`choco install innosetup --version <pinned>`); `tools/sign_windows.ps1` signs `ChopFractal.vst3\Contents\x86_64-win\ChopFractal.vst3` (the DLL) before packaging, then Inno signs `setup.exe` and the uninstaller (`SignTool=cfsign $f`, `SignedUninstaller=yes`). Modes: `azure` (uses `azure/trusted-signing-action` or `AzureSignTool`; secrets `AZURE_TENANT_ID`, `AZURE_CLIENT_ID`, `AZURE_CLIENT_SECRET`; variables `AZURE_SIGN_ENDPOINT`, `AZURE_SIGN_ACCOUNT`, `AZURE_SIGN_PROFILE`), `pfx` (secrets `WIN_SIGN_PFX_BASE64`, `WIN_SIGN_PFX_PASSWORD`, for an existing certificate only), `none` (default: build `-UNSIGNED`). All use `signtool sign /fd SHA256 /td SHA256 /tr http://timestamp.digicert.com` semantics (RFC 3161 timestamp so signatures outlive the certificate) and `signtool verify /pa /v` afterwards. Installer `installer/windows/ChopFractal.iss`: fixed `AppId={{GUID}}` (generated once, never changed), `AppVersion` from `/DAppVersion=%VERSION%`, `ArchitecturesInstallIn64BitMode=x64compatible`, `PrivilegesRequired=admin`, `DefaultDirName={commoncf64}\VST3\ChopFractal.vst3`, `DisableDirPage=yes`, files `recursesubdirs`, license file, `[UninstallDelete]` for the bundle, `CloseApplications=no` (DAWs hold the DLL: on a locked file the installer shows `"A DAW is using ChopFractal. Close your DAW and click Retry."`). Why Inno rather than WiX/MSI: free, scriptable on a stock runner, trivial per-machine VST3 payload; enterprise MSI is a later option.
**Linux:** only built when `SHIP_LINUX == "true"`; `tar czf` of the bundle; unsigned; same validator.
**JUCE-specific build notes:** `JUCE_VST3_CAN_REPLACE_VST2=0`, `JUCE_WEB_BROWSER=0`, `JUCE_USE_CURL=0` stay (no network code, important for notices); `COPY_PLUGIN_AFTER_BUILD` stays FALSE (installers install; CI never writes to system folders except in the installer test). High-DPI: JUCE handles; verified in the matrix. `FetchContent` of JUCE uses the pinned tag `8.0.15` (`GIT_SHALLOW`); releases additionally verify the fetched commit SHA equals `CHOPFRACTAL_JUCE_COMMIT` recorded in `plugin/CMakeLists.txt` (supply-chain pin; maintainer updates it with the tag).
**Crash-safe logging (`plugin/src/Log.cpp`):** file `<userApplicationDataDirectory>/ChopFractal/logs/chopfractal-YYYYMMDD.log` (Windows `%APPDATA%`, macOS `~/Library/Application Support`, Linux `~/.config`), UTF-8, one line per event `2026-10-10T14:03:11.123Z [INFO] message`, opened append-only and flushed after every line (`juce::FileOutputStream::flush`), guarded by a mutex (never on the audio thread; `processBlock` has no logging), each file capped at 1 MiB (then a new `-N` suffix), at most 7 files kept (oldest deleted on `init`). Logged: plugin load (version, build, sha, OS, host, sample rate, block size, buses), every `Notice` of Warning/Error level, status messages that start with `"Could not"`, state-restore failures, export/stretch/capture job outcomes. Never logged: user audio, file names outside the logs folder, project content. A `session.marker` file is created at `init` and removed in the processor destructor; if it exists at the next `init`, log `[WARN] The previous session ended unexpectedly.` (best-effort crash hint). The plugin installs NO process-wide crash handler (`juce::SystemStats::setApplicationCrashHandler` would override the DAW's own handler and is forbidden); the host's crash dump plus this log are the diagnostic path. Logging failures are swallowed (no exceptions, no dialogs).

## 7. Test plan
Automated:
- Shell tests (`plugin/tests/test_plugin_shell.cpp`, run on all three OSes): `version_stamp_matches_VERSION_file` (BuildInfo `kVersionFull` equals the file content read via a compile definition path), `log_files_are_capped_rotated_and_flushed` (write 3 MiB, assert <= 7 files each <= 1 MiB + one line, content readable without closing the logger), `log_never_throws_when_folder_is_unwritable`, `previous_session_marker_is_detected`, `existing_tests_pass_on_macos_and_windows` (all 13 current CHOP_TESTs; the editor test skips without a display).
- Script tests (`tools/tests/` run in `portability`): `check_version.py` accepts `0.1.0`, `0.2.0-beta.1`, rejects `v0.1`, `0.1`, tag mismatch; `check_notices.py` fails when the JUCE tag differs; `verify_bundle.py` unit-tested against a fake Info.plist.
- CI release rehearsal (`workflow_dispatch`, dry_run): builds both installers unsigned, installs silently on the runner (`installer -pkg ... -target /` with sudo on macOS; `ChopFractal-...-setup.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART` on Windows), runs `validate_vst3.sh` on the INSTALLED bundle, runs `verify_bundle.py`, uninstalls (Windows `unins000.exe /VERYSILENT`, macOS `rm -rf` documented), and asserts the bundle path no longer exists.
- Gate tests: `cmake -DCHOPFRACTAL_RELEASE=ON` with license `UNSET` exits non-zero with the exact message; `AGPL` with the proprietary `LICENSE_ID` exits non-zero.
- Size/time budgets recorded (warn, not fail): bundle <= 20 MB, pkg <= 25 MB, setup.exe <= 20 MB, CI plugin job <= 25 min with warm cache.
- Existing sanitizer/TSan jobs and golden hashes unchanged.
Manual real-DAW matrix (`docs/COMPATIBILITY.md`, one row per host x OS; Logic/AU is out of scope):
| Host | Version to test | macOS (arm64, and Intel/Rosetta host) | Windows 11 x64 |
|---|---|---|---|
| REAPER | 7.x | required | required |
| Ableton Live | 12 Suite/Standard | required | required |
| FL Studio | 2024+ | required | required |

Each cell is scored on this script (record pass/fail, build number, notes, screenshot of REAPER/Live scan result): 1) installer runs clean on a fresh user account; 2) host scan finds exactly one ChopFractal VST3 (no duplicates); 3) instantiate on stereo and mono tracks, no crash, no asserts, default state silent pass-through; 4) load a WAV, Smart Setup, Generate, play with host sync, tempo change 90->140 mid-play, loop wrap; 5) automate `density` and `variation_amount` (read back values), check `parameter IDs` unchanged against the manifest list; 6) save project, close host, reopen: pattern, history, embedded audio restored (embed on and off); 7) change sample rate 44.1 -> 48 -> 96 kHz and buffer 32 -> 2048 (including variable-size blocks): no glitches/stuck voices; 8) offline render/bounce is identical to real-time within host limits (record peak difference); 9) 4 instances at once; 10) open/close editor 20 times, resize/high-DPI move between monitors: no leak growth > 5 MB, no crash; 11) after F11/F12/F13 land: aux outputs (Live/REAPER routing), capture (Synced and Free), MIDI/WAV drag-out; 12) uninstall via the OS; host rescan shows it gone. Any failing cell opens a GitHub issue labelled `compat` and blocks the release until fixed or documented as a known limitation in release notes.

## 8. Acceptance criteria
- [ ] CI builds the VST3 on Linux, macOS (arm64+x86_64 universal, `lipo -archs` shows both) and Windows (x64, static CRT) from the same commit; validator reports 0 failed tests on all three.
- [ ] `VERSION` is the only place a version is typed; changing it changes plugin bundle metadata, installer names/versions and About box (test + script check); `check_version.py` blocks mismatched tags.
- [ ] Release build with `CHOPFRACTAL_JUCE_LICENSE=UNSET` or AGPL-with-proprietary-LICENSE fails to configure with the documented message.
- [ ] Tagged release run (with maintainer-provided credentials) produces a notarized, stapled `.pkg` (`spctl` accepted, `stapler validate` ok), a Windows `setup.exe` with a valid Authenticode signature and timestamp (`signtool verify /pa`), `SHA256SUMS.txt`, and `THIRD_PARTY_NOTICES.txt`, attached to a draft GitHub Release; no secret appears in any log (`gh run view --log | grep` of known secret fragments in a rehearsal).
- [ ] Installed-bundle validation and silent uninstall rehearsal pass on both OSes.
- [ ] Manual matrix: every required cell is pass or has a documented, accepted limitation; results committed in `docs/COMPATIBILITY.md`.
- [ ] Logging: bounded (7 x 1 MiB), flushed per line, never on the audio thread (code review + the existing allocation test still passes), no process-wide crash handler installed.
- [ ] `build-test` windows-msvc job runs with warnings as errors; all existing ctest targets, golden hashes 2397844821793184813, 12084884237330071892, 13710596758976548913, 18237151833431327128, and state compatibility unchanged.

## 10. Risks and mitigations
- No Apple/Windows credentials yet: all work through step 6 produces unsigned artifacts and is verifiable; steps 7-10 are blocked on section 3 items, and the release workflow degrades to `dry_run`.
- Notarization rejection (unsigned nested code, missing hardened runtime, missing timestamp): fail the job with the `notarytool log`; the plugin has a single Mach-O so risk is low.
- Rosetta missing on runners, or macOS runner image changes: fall back to manual Intel row; pin runner labels (`macos-14`, `windows-2022`).
- Windows locked-DLL installs and AV false positives for unsigned builds: signed builds only for release, "Retry" message, timestamping.
- JUCE license: shipping closed source without a commercial license is a legal blocker; the gate and repository variable make the decision explicit and auditable.
- JUCE FetchContent availability/supply chain: commit pin check, cache, optional `-DCHOPFRACTAL_JUCE_DIR` for offline builds.
- Hosts differ on mono layouts, variable block sizes and window scaling: covered by matrix steps 3, 7, 10; fix forward, no host-specific code paths without an issue.
- Log file growth or privacy concerns: caps, no user content, no upload.

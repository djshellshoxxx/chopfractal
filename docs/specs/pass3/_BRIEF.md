# Pass-3 feature briefs (input for spec authors)

Four features, built on the CURRENT code (the F00 editor decomposition is NOT done; all editor code lives in plugin/src/PluginEditor.cpp/.h, new logic goes into new files). Specs go in docs/specs/pass3/<ID>-<slug>.md using _TEMPLATE.md (all 11 sections).

- **P1 chaos-macro (fun):** one automatable `chaos` host parameter (0..1, manifest version 3, appended after `fx_intensity`, default 0) that, when above 0, deterministically pushes the *effective* generation settings used by Generate, Mutate and Evolve steps toward more variation: variation levels, density wobble, probability/magnitude of effects and retrigger/pitch/reverse allowances. A pure mapping function `pattern::Settings applyChaos(const Settings& base, double chaos)` in composition (new file composition/src/chaos.cpp). chaos == 0 must return the input untouched so all golden hashes stay unchanged. A "Chaos" slider in the editor plus a "Reroll" button (new seed + Generate with the current chaos). No new audio-thread work.
- **P2 midi-wav-drag-out (valuable):** drag the current pattern as a .mid (and a rendered .wav) from the editor straight into a DAW track. Refactor the MIDI construction inside ProjectSession::exportKit into reusable `Result<std::vector<std::uint8_t>> ProjectSession::renderMidi(const KitOptions&) const` and `renderWavBytes(const ExportWavOptions&) const` (byte-identical output for exportKit, tested), a temp-file helper in plugin (create in the system temp dir under `ChopFractal/drag/`, unique names, cleanup of files older than 7 days at editor construction), editor "Drag MIDI" and "Drag WAV" handle components that call `juce::DragAndDropContainer::performExternalDragDropOfFiles` on mouse drag (the editor becomes a DragAndDropContainer), disabled with a tooltip when there is no pattern.
- **P3 presets (usable):** preset save/load/delete with a browser combo. New portable module `modules/preset_store` (no JUCE): `Preset{name, pattern::Settings subset, fractal motif/depth/mutation/accent decay, evolve every/amount, chaos}`, versioned binary serialization with bounds checks, six factory presets (names and values in the spec) that validate against `pattern::validateSettings`, `serialize/deserialize`, name sanitizing for file names. Plugin: user presets stored as `.cfpreset` files in `juce::File::getSpecialLocation(userApplicationDataDirectory)/ChopFractal/Presets`; editor combo (factory entries first, then user entries), Save (name prompt), Delete (user presets only). Loading a preset sets the corresponding APVTS parameters and editor fields; it never changes the pattern until Generate is pressed.
- **P4 direct-hit-editing (essential missing):** edit hits directly in the pattern grid. Drag a hit horizontally to move it (snap to the pattern grid, stays inside its bar), vertically to change its chop (lane), drag its right edge to resize, Delete/Backspace deletes the selected hit, double-click on an empty spot creates a hit one grid cell long on that lane, Ctrl/Cmd+D duplicates. Everything routes through ProjectSession::edit with pure pattern_engine functions; add `pattern::resizeEvent`, `pattern::duplicateEvent`, `pattern::setEventEnabled` (mute) beside the existing addEvent/moveEvent/deleteEvent/setEventChop; locked scopes refuse; each completed gesture is one undo step and one `commitEdit`. Also fix the waveform click behavior: single click auditions the chop under the cursor, **Shift+click** (not plain click) adds a marker, Alt+click deletes the nearest marker, double-click no longer adds markers. Add a mouse-simulation helper to the GUI test harness (synthesized MouseEvents on the editor at component coordinates) and use it in the tests.

Common rules for all four: portable modules have no JUCE; the audio thread allocates and locks nothing; deterministic from seeds; golden hashes 2397844821793184813, 12084884237330071892, 13710596758976548913, 18237151833431327128 must not change; parameter IDs are append-only; saved state stays backward compatible and feature-free state serializes unchanged (preset_store is stored in files, not project state; chaos is an APVTS parameter).
